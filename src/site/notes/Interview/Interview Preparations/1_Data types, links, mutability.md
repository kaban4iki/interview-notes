# Ссылочная семантика и Mutability

В Python нет переменных в классическом понимании (как выделенных ячеек памяти). Есть объекты и имена (ссылки), которые на них указывают. Операция присваивания (`=`) никогда не копирует данные, она лишь привязывает имя к объекту.

**Изменяемость (Mutability)** определяет, может ли объект изменить свое состояние в выделенной ему области памяти без изменения `id()` (адреса).

- **Immutable (int, str, tuple, frozenset, bytes):** При попытке изменения создается новый объект, ссылка перезаписывается.
    
- **Mutable (list, dict, set, bytearray):** Изменяются in-place (на месте).

```python
# Перепривязка ссылки для immutable
a = 10
print(id(a)) # Адрес X
a += 1
print(id(a)) # Адрес Y (создан новый объект)

# Изменение in-place для mutable
lst = [1, 2]
print(id(lst)) # Адрес Z
lst += [3]     # Вызов __iadd__, изменение на месте
print(id(lst)) # Адрес Z (тот же объект)

lst = lst + [4] # Вызов __add__, создание нового списка
print(id(lst))  # Адрес W (новый объект)
```

# Кэширование объектов (Interning)

Для оптимизации потребления памяти и скорости работы CPython предварительно создает и кэширует некоторые часто используемые иммутабельные объекты.

1. **Small Integer Caching:** Числа от `-5` до `256` (включительно) кэшируются при старте интерпретатора. Все ссылки на число `100` будут указывать на один и тот же объект в памяти.
    
2. **String Interning:** Строки, состоящие только из ASCII-букв, цифр и нижних подчеркиваний, кэшируются. Строки, вычисляемые в runtime (конкатенация), могут не кэшироваться автоматически.

```python
a = 256
b = 256
print(a is b)  # True (из кэша)

c = 257
d = 257
print(c is d)  # False (созданы новые объекты)
# Примечание: в REPL будет False. Внутри одного файла (модуля) компилятор 
# может оптимизировать константы, и c is d выдаст True.

s1 = "hello_world"
s2 = "hello_world"
print(s1 is s2) # True (интернировано)
```

# Хешируемость (Hashability)

Хешируемый объект — это объект, который имеет неизменное хеш-значение на протяжении всего жизненного цикла (реализует `__hash__()`) и может сравниваться с другими объектами (реализует `__eq__()`).

Это строгое требование для ключей словарей (`dict`) и элементов множеств (`set`). По умолчанию все пользовательские классы хешируемы (хеш берется от `id()`). Встроенные мутабельные типы (`list`, `dict`) нехешируемы — их `__hash__ = None`.

**Контракт хеширования:**

1. Если `a == b`, то `hash(a) == hash(b)`.
    
2. Обратное неверно: если `hash(a) == hash(b)`, объекты могут быть не равны (это коллизия).

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y
        
    # Как только мы переопределяем __eq__, класс теряет хешируемость по умолчанию.
    def __eq__(self, other):
        return self.x == other.x and self.y == other.y
        
    # Для возврата хешируемости нужно явно определить __hash__
    def __hash__(self):
        return hash((self.x, self.y))

p1 = Point(1, 2)
p2 = Point(1, 2)
d = {p1: "data"}
print(d[p2]) # Выведет "data" благодаря правильным __hash__ и __eq__
```

# Задачи

### Задача 1. Опасность изменяемых объектов по умолчанию (Default Mutable Arguments)

**Условие:** Что выведет код и почему? Как это исправить?

```python
def add_item(item, lst=[]):
    lst.append(item)
    return lst

print(add_item(1))
print(add_item(2))
print(add_item(3, []))
print(add_item(4))
```

**Разбор механики:** Код выведет: `[1]`, `[1, 2]`, `[3]`, `[1, 2, 4]`. Значения по умолчанию для аргументов функции вычисляются **один раз на этапе компиляции** (чтения) модуля и парсинга определения функции `def`. Этот объект списка сохраняется в атрибуте функции `add_item.__defaults__`.

При вызове без второго аргумента функция каждый раз обращается к одному и тому же списку в памяти.

```python
# Правильное решение
def add_item_fixed(item, lst=None):
    if lst is None:
        lst = []
    lst.append(item)
    return lst
```

### Задача 2. Аномалия мутабельности внутри иммутабельного контейнера

**Условие:** Дан кортеж `t = (1, 2, [3, 4])`. Выполняется операция `t[2] += [5, 6]`. Что произойдет?

```python
t = (1, 2, [3, 4])
try:
    t[2] += [5, 6]
except Exception as e:
    print(repr(e))
print(t)
```

**Разбор механики:** Произойдут **сразу две вещи**:

1. Будет выброшено исключение `TypeError: 'tuple' object does not support item assignment`.
    
2. Список внутри кортежа **изменится**, и `print(t)` выведет `(1, 2, [3, 4, 5, 6])`.
    

Почему так происходит? Операция `+=` раскладывается на 4 шага (инструкции байткода CPython):

1. Чтение значения по индексу: `STORE = t[2]` (успешно, получена ссылка на список).
    
2. Вызов метода модификации IN-PLACE: `NEW_VAL = STORE.__iadd__([5, 6])` (список успешно расширяется на месте).
    
3. Инструкция присваивания результата обратно в кортеж: `t[2] = NEW_VAL` (здесь кортеж блокирует присваивание и выбрасывает `TypeError`).
